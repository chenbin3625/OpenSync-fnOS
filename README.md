## 它能做什么

- **备份照片和文档** —— 将 NAS 上的新增或修改文件同步到网盘或另一块磁盘，保留目标端已有的文件。
- **下载与归档** —— 将网盘更新持续同步到 NAS，也可在两个网盘之间建立单向同步任务。
- **维护镜像目录** —— 在单向任务中开启「同步删除」，按源端内容清理目标端多余文件。
- **双向协作** —— 在两个可读写的目录之间同步新增、修改和删除，保留冲突副本供后续处理。

## 安装

### 安装前准备

- 飞牛 fnOS **1.2.0401 或更高版本**；
- 在飞牛「应用设置 → 文件夹访问权限」中为 OpenSync 授予需要同步的本地文件夹读写权限；
- 需要通过第三方 WebDAV 接入的网盘可使用自建 OpenList / AList。参见[国内网盘接入](#国内网盘接入)。

### 下载安装包

| 设备架构 | 安装包 |
| --- | --- |
| x86 / amd64（Intel、AMD） | [opensync-amd64.fpk](https://github.com/chenbin3625/OpenSync-fnOS/releases/latest/download/opensync-amd64.fpk) |
| ARM / arm64 | [opensync-arm64.fpk](https://github.com/chenbin3625/OpenSync-fnOS/releases/latest/download/opensync-arm64.fpk) |

不确定设备架构？在飞牛的系统信息中查看处理器型号：Intel、AMD 选 amd64，ARM 处理器选 arm64。也可以前往 [Releases](https://github.com/chenbin3625/OpenSync-fnOS/releases) 查看全部版本。

### 安装步骤

1. 在飞牛中打开「应用中心」，选择「手动安装」，上传下载好的 `.fpk` 文件。
2. 等待安装完成，在应用列表中找到 **OpenSync** 并打开。
3. 在飞牛「应用设置 → 文件夹访问权限」中为 OpenSync 授权需要访问的本地目录。

安装包同时提供 `SHA256SUMS` 校验文件，熟悉命令行的用户可以自行校验完整性。

## 快速上手

下面以「把 NAS 上的照片备份到云端或另一块磁盘」为例，第一次配置只需几分钟。

### 1. 授权 NAS 文件夹

在飞牛「应用设置 → 文件夹访问权限」中给 OpenSync 授权要同步的文件夹。本地磁盘互备需要授权两端目录。返回同步向导后可点击「刷新目录」。

### 2. 新建同步任务

打开「同步工作台」，选择左侧的连接，再点击「新建同步任务」。可以先用「添加连接」接入网盘，也可以在任务向导内添加。

1. **选择同步文件夹**。选定 NAS 和云端目录。选中的连接会带入向导。本地互备、云对云及多源多目标可切换到自由模式。
2. **确认方向与文件处理**。核对同步方向、实际目标位置、删除与同名文件的处理方式。需要自定义轮询、计划、限速或过滤时，打开「进阶设置」。保存后可在当前连接查看任务的首次目录核对和传输状态。

默认使用单向增量同步，保留目标端独有的文件。同名文件可能更新。双向同步会在两端传播删除。

### 3. 预览并核对结果

首次开启「镜像对齐」会将任务保存为暂停状态。查看只读预览后，可确认启动镜像。镜像会清理目标端独有文件。

在「同步工作台」选中连接后，可在「任务列表」「同步历史」「连接设置」间切换。批量同步和中止按当前列表或勾选项执行。点击任务名称打开详情，可查看进度、暂停、恢复或发起「数据一致性校验」，在「同步记录」核对文件明细。

### 4. 配置通知（可选）

在「通知配置」添加渠道并点击「测试」。按需在任务的「同步设置」绑定渠道，或使用全局已启用的渠道。

### 存储管理

选中连接后，在「连接设置」测试连接、查询空间、编辑凭据、浏览和恢复文件。配置导入和导出等功能位于「全部连接 → 连接设置 → 高级存储管理」。选中「本地目录互备」，可在「连接设置 → 管理授权目录」刷新飞牛授权目录。

S3 和 QingStor 可选择显式密钥、运行时凭据或匿名访问。运行时凭据由应用环境提供（如 `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`、`RCLONE_QINGSTOR_ACCESS_KEY_ID` / `RCLONE_QINGSTOR_SECRET_ACCESS_KEY`）。OCI 用户主体认证需在应用环境设置 `RCLONE_OOS_CONFIG_FILE` 的绝对路径，可用 `RCLONE_OOS_CONFIG_PROFILE` 选择配置节；OCI 配置中的私钥文件也应使用绝对路径。实例主体认证适用于已获授权的 OCI 实例。

「导入 rclone.conf」支持明文和加密配置。导出的配置使用当前 NAS 的本地绝对路径，迁移设备时需要调整路径并重新配置运行时凭据。夸克网盘、123 云盘及依赖它们的组合存储请通过「设置」中的 JSON 备份迁移。

## 国内网盘接入

在「同步工作台 → 添加连接」选择所需存储。

| 存储 | 配置方式 |
| --- | --- |
| **夸克网盘** | 使用夸克 App 扫码登录，或填写网盘 Cookie，支持运行时续期 `__puus`。可填写 FID 限定根目录。本地上传支持秒传和顺序分片直传，多个文件可并行上传。 |
| **123 云盘** | 默认使用开放平台 OpenAPI，可填 Client ID 与 Client Secret 自动获取并续期令牌，也可直接填 Access Token。个人盘 Web 协议支持手机号或邮箱与密码，也可填写 Web Access Token。两种协议均可指定数字根目录 ID，默认 `0`。本地上传支持秒传与并发分片，OpenAPI 直链下载需要开通直链空间权益。 |
| **OpenList / AList (WebDAV)** | 可接入阿里云盘、百度网盘、115 等由自建服务挂载的网盘。填写 WebDAV 地址和账号密码，同机地址通常为 `http://127.0.0.1:5244/dav`。 |

123 云盘仅填写令牌时，令牌失效后需要更新凭据。将 OpenList / AList 等标准 WebDAV 用作目标存储时，新任务默认仅按文件大小比对。

## 持续同步

- **检测变更**。本地授权目录使用文件系统监听，双向任务监听两端的本地目录。无法可靠监听时改用轮询。远端检测默认每 60 秒一次，可设为 10–86400 秒。完整核对默认每 1440 分钟一次，可设为 1–10080 分钟。文件变动默认合并等待 30 秒。
- **按需传输**。已知的文件变更可直接核对受影响路径，必要时扫描两端目录。修改文件后按文件传输。
- **补齐与重试**。待处理变更和检测索引保存在数据库中，应用重启、任务恢复或运行窗口重新开放后会补齐变更。传输失败可自动退避重试，间隔由 10 秒逐步增加，最长 1 小时。
- **运行窗口**。可限制传输时段，支持跨午夜。窗口外的变更等到下一个窗口处理，并可选择在窗口结束时中止当前批次。

远端检测成本随目录和文件数量增长。对夸克网盘，任务表单建议将远端检测间隔设为至少 300 秒以降低限流概率。普通 WebDAV 缺少可靠时间或哈希时，同大小的修改可能漏检。可通过「数据一致性校验」的下载比对复核内容，下载会消耗额外流量。

## 同步方向与删除策略

| 方向 | 数据流向 | 删除行为 |
| --- | --- | --- |
| **单向同步** | 源目录 → 目标目录，支持本地和远端任意组合 | 由「同步删除」控制 |
| **双向** | 两个可读写目录互相同步新增、修改和删除 | 两端均可传播删除，受双向删除保护约束 |

### 单向同步

关闭「同步删除」时使用增量复制，保留目标端多余文件。开启后使用镜像同步，复制新增和修改，并清理目标端多余文件。开启回收站时，删除或覆盖的旧文件可移入目标端的回收站子目录。

镜像任务会检查扫描结果和源目录是否异常变空。达到保护条件时会保留目标项并报告失败。需要先清理同路径的文件与目录冲突时，如果该目标项受过滤规则保护，也会保留并报告失败。

### 双向同步

首次运行会扫描两端并建立基线，补齐单端独有的文件，按设置处理同名冲突。之后以 SQLite 中的上次同步基线和两端现状做三方比对。一端删除、另一端修改同一文件时优先保留修改。同步根目录或存储身份变化会重新建立基线，磁盘挂载发生变化或原有文件较多的目录异常变空时会阻止本轮同步。

双向任务限一个源目录和一个目标目录，两端都需要读写权限。选择双向时默认保留双方冲突副本，可在「同步策略与回收站」中调整冲突策略和启用双端回收站。「同步设置」中可调整单端批量删除保护阈值，默认在计划删除至少 5 个文件且达到基线文件数的 50% 时跳过该端的删除。

在任务菜单打开「冲突处理」，可查看内容冲突、文件名大小写、文件与目录同名及文件名兼容性问题。带副本的内容冲突可选择保留左侧、右侧或双方文件。其他冲突可在处理后标记为已处理。

## 旧任务升级

- 已有的固定间隔、Cron 和手动任务继续按原计划运行，编辑保存时也保留执行方式。旧移动任务仍会先复制并校验，再删除源文件。新建任务使用持续同步。
- 旧镜像任务若启用了「定时全量删除确认」，将保留目标端待清理项。确认允许直接删除后，可在 `config.ini` 的 `[opensync]` 中将 `scheduled_full_sync_confirm` 设为 `0` 并重启应用。
- 关联旧版 OpenList 引擎的任务会停用。请在「同步工作台 → 添加连接」通过 OpenList / AList WebDAV 模板接入对应目录，再创建持续同步任务。

## 文件夹同步路径规则

在新建或编辑任务的「基础与路径」步骤中，选好源路径和目标路径后，下方的**同步位置预览**会实时展示每个源目录最终同步到的目标位置，并高亮自动追加的子目录层级。

不同选择组合的映射规则如下：

| 场景 | 源路径示例 | 目标路径示例 | 实际同步目标位置 | 说明 |
| --- | --- | --- | --- | --- |
| **单个源目录** | `/Photos` | `/Backup` | `/Backup/` | 源目录里的文件和子目录**直接同步到目标目录下**，不会额外创建 `/Backup/Photos/`。例如 `/Photos/a.jpg` 会同步为 `/Backup/a.jpg` |
| **多源 · 有共同父目录（同级）** | `/drive/2`、`/drive/学习` | `/backup` | `/backup/2/`、`/backup/学习/` | 自动省略共同父目录 `/drive`，避免在目标端多套一层父目录 |
| **多源 · 有共同父目录（含深层）** | `/nas/docker`、`/nas/common/sec` | `/google` | `/google/docker/`、`/google/common/sec/` | 只省略最深共同父目录 `/nas`，保留其后的相对目录层级，防止不同分支下的同名目录合并覆盖 |
| **多源 · 无共同父目录（末级不同名）** | `/media/photos`、`/archive/videos` | `/backup` | `/backup/photos/`、`/backup/videos/` | 没有除 `/` 外的共同父目录时，按各源目录的末级文件夹名在目标下建子目录 |
| **多源 · 无共同父目录（末级同名）** | `/a/docs`、`/b/docs`、`/media/photos` | `/backup` | `/backup/a/docs/`、`/backup/b/docs/`、`/backup/photos/` | 末级文件夹同名冲突时，同名项自动保留完整路径以防互相覆盖；不重名项仍只保留末级名称 |
| **多个目标目录** | `/media/photos`、`/archive/videos` | `/b1`、`/b2` | `/b1/photos/`、`/b1/videos/`、`/b2/photos/`、`/b2/videos/` | 单向任务会按以上规则将每个源目录同步到每个目标目录 |

### 编辑已有任务时的位置锁定

任务保存后，OpenSync 会记录当前每个「源目录 → 目标目录」的实际落点。之后编辑任务时：

- **只增删源路径、不修改目标路径**：保留下来的源目录会继续**沿用原目标位置**（编辑器预览中会标记「沿用原位置」），新增的源目录按当前选择计算落点。这样可以避免因增删源目录导致共同父目录变化，进而触发整目录重传或在全量同步中误删旧目录。
- **修改目标路径**：一旦目标路径列表发生增删、改动或顺序变化，所有源目录都会按最新规则重新计算目标位置。
- **单源扩成多源的注意事项**：如果原任务是单源直接落到目标根目录（如 `/Photos` → `/Backup/`），在不改目标路径的前提下新增第二个源目录（如 `/Docs` → `/Backup/Docs/`），由于 `/Backup/` 包含 `/Backup/Docs/`，系统会拦截该配置；此时调整目标路径重新分配，或为新目录单独建任务即可。

### 路径冲突限制

为避免同一目录树被并发写入或在全量同步中被误删，以下配置会在预览中提示并禁止保存：

- **源目重叠或互含**：源目录与目标目录不能相同或互相包含（不区分大小写，例如 `/Photos` 与 `/photos` 视为同一目录）；
- **多源互含**：多个源目录之间不能互相包含（如同时选 `/Photos` 和 `/Photos/2024`）；
- **最终目标位置互含**：不仅配置的多个目标目录之间不能互相包含（如 `/Backup` 与 `/Backup/Nightly`），多源推导出的最终落点之间也不能互相包含（例如 `/x/a`、`/y/a`、`/z/x` 同步到 `/D` 会分别落到 `/D/x/a/`、`/D/y/a/` 和 `/D/x/`，其中 `/D/x/` 包含 `/D/x/a/`）；
- **跨任务目标冲突**：同一存储引擎下，不同任务的最终目标位置之间同样不能互相包含。

## 文件过滤

被过滤掉的源文件不会复制；全量同步也不会删除或覆盖被排除规则过滤掉的目标内容。仅因大小范围被跳过的同名目标文件例外：源文件进入范围后会被更新，不再被旧的目标副本挡住。即使目标父目录只在目标端存在，清理时也会保留其中被排除的文件和目录。相关设置位于任务编辑器的「过滤规则」中。

### 按大小过滤

可以分别设置「排除小于」和「排除大于」的文件大小，例如跳过 10 KB 以下的缩略图和 10 GB 以上的超大文件。

### 按文件类型过滤

界面内置了常用分组，勾选即可排除：

- 系统文件：`.DS_Store`、`._*`、`Thumbs.db`、`Desktop.ini` 等；
- 音乐、视频、图像、文档、压缩文件、可执行文件等常见类型。

也可以在下方输入框添加自定义规则，支持简单的 `*` 通配符：

| 规则 | 作用 |
| --- | --- |
| `Thumbs.db` | 忽略所有同名文件 |
| `._*` | 忽略以 `._` 开头的文件 |
| `*.tmp` | 忽略所有 `.tmp` 后缀的文件 |

> 自定义输入只支持文件名和后缀规则，不支持 `!` 反选、字符集、正则表达式等复杂语法，保存时会提示并拒绝不支持的写法。需要忽略文件夹时，请使用下面的「文件夹过滤」。

### 按文件夹过滤

在「文件夹过滤」中展开源目录树，勾选要忽略的子文件夹即可。规则只针对源目录，未勾选的文件夹会正常同步。

### 系统目录过滤

一键忽略常见的系统和 NAS 目录，包括：

- macOS：`.Spotlight-V100/`、`.Trashes/`、`.fseventsd/` 等；
- Windows：`$RECYCLE.BIN/`、`System Volume Information/`；
- NAS 回收站：`#recycle/`、`@Recycle/`、`.Trash/` 等；
- 其他：`lost+found/`、`@eaDir/` 等。

## 任务状态与通知

### 三种查看视图

- **总览** —— 查看同步方向、目录、监测状态和最近执行情况，可立即同步、暂停或恢复同步、编辑配置。
- **实时任务** —— 查看进度、速度、传输量和逐文件状态，支持动态限速、暂停或继续传输，以及中止本次同步。
- **历史任务** —— 按日期、状态或任务 ID 筛选记录，可查看逐文件明细，按操作类型、对象类型或关键词筛选，并导出 CSV。

单向任务可在历史记录中重试失败项。文件项直接重试，目录项会重新扫描和比较，镜像删除需要重新执行同步。双向任务失败后请重新运行整个任务，由系统按当前两端状态重新核对。

「数据一致性校验」可核对两端文件，并导出差异结果。单向任务可按校验结果对目标端的差异或缺失文件发起定向修复。「同步设置」中也可配置每日、每周或每月自动校验。

### 通知渠道

支持 12 种通知渠道。每个渠道可选择「全部事件」「仅异常 / 失败」或自定义事件，并设置消息模板。任务级渠道绑定与关闭通知可在「同步设置」中配置。

| 渠道 | 适合场景 | 需要准备 |
| --- | --- | --- |
| 钉钉机器人 | 家庭群、团队群 | Webhook 地址，可选加签密钥 |
| 企业微信（应用） | 企业微信成员推送 | CorpID、CorpSecret、AgentID |
| 企业微信群机器人 | 企业微信群 | 群机器人 Webhook 地址 |
| 飞书 / Lark | 团队群 | Webhook 地址，可选签名密钥 |
| Telegram 机器人 | 个人或群组推送 | Bot Token、Chat ID，可选自建 API 地址 |
| SMTP 邮件 | 邮箱通知 | SMTP 服务器、端口、发件人/收件人邮箱与授权码 |
| Server酱 | 微信推送 | SendKey |
| Bark | iPhone 推送 | Device Key，可自建服务器 |
| ntfy | 轻量自托管/移动推送 | Topic 主题，可选自建服务器与 Token |
| Gotify | 自托管推送服务 | 服务器地址与 App Token |
| PushPlus | 微信/多端推送 | Token |
| 自定义 Webhook | 接入自建服务或自动化平台 | URL，支持 GET / POST / PUT |

通知异步投递，列表会显示最近一次投递状态。通知可包含任务状态、源和目标路径、传输统计及失败项摘要。

「设置」支持每天或每周发送同步汇总，也可点击「立即发送一次摘要」。摘要会发往启用且订阅摘要事件的渠道。

## 系统设置

在「设置」页面可以调整任务执行参数、管理配置备份与查看应用日志。

| 设置项 | 默认值 | 说明 | 调整建议 |
| --- | --- | --- | --- |
| 操作并发数 | 5 | 同时执行的复制、删除、移动操作数量（单个任务可覆盖） | 网盘限速或频繁失败时调低 |
| 扫描并发数 | 16 | 同时扫描源端和目标端目录的请求数量（单个任务可覆盖） | 大目录或接口不稳定时调低 |
| 失败重试次数 | 2 | 单个文件操作失败后的最大重试次数（单个任务可覆盖） | 网络不稳定时可调到 3–5 |
| 任务超时 | 48 小时 | 任务超过该时长后自动标记为超时 | 首次超大同步可调高，`0` 表示不限制 |
| 存储健康检查周期 | 15 分钟 | 后台定时探测内置 rclone 与各远程存储在线状态和延迟的周期 | `0` 表示关闭定时巡检 |
| 任务记录保留 | 30 天 | 历史任务记录保留天数 | `0` 表示不自动清理 |
| 本地磁盘最大并发任务 | 0 | 限制同时读写本地授权目录的任务数 | `0` 表示不限 |
| 目标磁盘最低预留空间 | 0 MB | 对能报告剩余空间的单向任务目标执行容量检查 | `0` 表示关闭检查 |
| 重启后自动续跑中断任务 | 关闭 | 应用恢复运行时重新处理启用任务的异常中断执行 | 单向任务可从未完成项续跑 |

- **全局总带宽与代理**。继承全局带宽规则的活跃传输共享限速额度，支持分时限速。远程存储可配置 HTTP、HTTPS 或 SOCKS5 代理，本地授权目录直连。
- **配置备份与恢复**。可将系统设置、存储、通知渠道和任务配置导出为 JSON。默认省略密钥等敏感字段，迁移凭据时可选择包含密钥。导入时可跳过或覆盖同名项。
- **应用运行日志**。按级别、行数和关键词筛选日志，支持下载日志。

## 常见问题

### 必须安装 OpenList 吗？能不能直接连网盘？

夸克网盘、123 云盘以及内置 `rclone` 支持的存储可以直接添加。阿里云盘、百度网盘、115 等可通过自建 OpenList / AList 的 WebDAV 接入。参见[国内网盘接入](#国内网盘接入)。

### 为什么看不到飞牛本地目录？

请在飞牛「应用设置 → 文件夹访问权限」中为 **OpenSync** 授权需要访问的文件夹，再打开「同步工作台 → 本地目录互备 → 连接设置 → 管理授权目录」，点击「刷新目录」。

### 使用 OpenList / AList（WebDAV）同步会拉取大量文件到本地比对吗？

OpenList / AList 等标准 WebDAV 作为目标时，新任务默认仅按文件大小比较，以减少读回远端文件的流量。同大小的修改可能漏检。需要逐文件复核内容时，可使用「数据一致性校验」并开启下载比对。

### 开启「同步删除」后，哪些文件会被清理？

镜像同步会清理目标端多余且未受过滤规则保护的内容。首次开启时，可在「镜像影响预览」中检查待清理项。需要保留被删文件时可启用任务回收站。参见[同步方向与删除策略](#同步方向与删除策略)。

### 同步速度慢怎么办？

速度主要取决于设备上行带宽、远端存储的接口限速以及并发/分流配置。可在任务「高级选项」中按需调整操作并发数、单文件多线程流数（`--multi-thread-streams`）、`--fast-list` 或限流参数（`--tpslimit` / `--bwlimit`）。

### 任务失败了怎么办？

先到「历史任务」查看失败明细。修复凭据、权限或网络等问题后，单向任务可重试未完成项，双向任务可点「立即同步」重新核对两端。

### 任务运行中可以停止吗？

「中止本次同步」结束当前批次，之后仍会检测变更。需要停止监测时，在任务总览点击「暂停同步」，它也会中止正在运行的批次。「恢复同步」会自动补齐暂停期间的变更。已传输的文件会保留。

### 升级会丢失配置和任务吗？

不会。使用新版本安装包覆盖升级会保留存储配置、任务、通知和历史记录，升级前应用还会自动备份数据。升级过程会自动停止并重新启动应用。

### 卸载会删除我同步的文件吗？

不会。卸载只会移除 OpenSync 应用本身，不会删除源目录或目标目录里的文件。应用配置和历史记录保存在飞牛的应用数据目录中，是否保留以飞牛卸载时的提示为准。

### 文件和凭据保存在哪里？

远程存储密钥和通知凭据加密保存在应用数据中。同步文件在任务指定的存储之间传输，通知发送到已配置的服务。导出包含密钥的配置备份时，请妥善保管备份文件。

<summary>本地开发与打包（开发者）</summary>

开发环境需要 Node.js 22.12+ 和 [backend/go.mod](backend/go.mod) 指定的 Go 版本。

```bash
npm run dev                    # 启动 Go 后端和 Vite 前端，缺少前端依赖时自动安装
npm --prefix frontend ci       # 首次单独使用 mock 时安装前端依赖
npm run dev:mock               # 仅启动前端，使用内置 mock 数据
```

`npm run dev` 默认监听局域网，入口为 `http://<本机局域网 IP>:3020/app/opensync/`。开发环境连接真实存储时，可用 `OPENSYNC_RCLONE_BIN` 指定 rclone 可执行文件的绝对路径。Mock 使用 Service Worker，应以本机 localhost 访问，或使用受信任的 HTTPS 地址。

### 飞牛打包

在 Linux 打包环境安装 fnpack 1.2.3，将可执行文件放到 `.tools/fnpack`，或用 `FNPACK` 指定路径。下载和校验方式参见[发布工作流](.github/workflows/release.yml)。打包脚本会构建前端、交叉编译后端，并将 rclone 打入对应架构的安装包。

```bash
npm run package:amd64          # dist/opensync-amd64.fpk
npm run package:arm64          # dist/opensync-arm64.fpk
```

前端使用 React 19、TypeScript、Vite 和 Semi Design，后端使用 Go、Gin、SQLite 和 robfig/cron。
